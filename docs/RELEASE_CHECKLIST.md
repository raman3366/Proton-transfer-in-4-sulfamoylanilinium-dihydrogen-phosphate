# Release checklist

This list separates publication of the available repository from a future archival deposit or accepted manuscript. Do not infer acceptance or a public trajectory deposit from a successful Git push.

## Repository preparation

- [x] Existing Git history and intended public GitHub destination inspected.
- [x] Original supplementary ZIP/PDF retained; all 749 ZIP members preserved.
- [x] Fuller research-machine package recovered and source checksums verified.
- [x] Main/SI tables, genuine DFT outputs and source-linked numerical exports included.
- [x] Nine primary, two sensitivity, two validation and other MD records distinguished.
- [x] Provisional/unconverged/failed scientific records retained and explained.
- [x] Citation authors/ORCIDs sourced from SI; CFF schema and ORCID check digits validated.
- [x] Original-code/data licenses authorized; third-party notices separated.
- [x] Credential/privacy scan and flagged-location review completed.
- [x] Relative-path reconstruction and stored-result consistency checks completed.
- [x] Full MD payload excluded from ordinary git; fresh external inventory prepared.
- [x] Final inventory and complete staged-tree review passed; the delivery report records the pushed commit and remote verification.

## Before an archival release or final manuscript submission

- [ ] Confirm submission status and revise metadata if a manuscript identifier exists.
- [ ] Deposit full trajectories and associated systems with a persistent identifier.
- [ ] Verify downloaded deposit files against the external and bundle inventories.
- [ ] Add the actual DOI and repository commit to the data-availability statement.
- [ ] Update the manuscript's historical “not deposited publicly” package statement.
- [ ] Choose an archival release version and archive that exact Git revision.
- [ ] On later acceptance/publication, add the verified article DOI and preferred citation.

End-to-end scientific reproduction is not checked off: no DFT, docking or MD run was authorized or executed during preparation. A GitHub release/tag or Zenodo DOI is not invented by this checklist.
